1. Overview

The app helps authorized forestry staff extract selected information from FMP and FIA PDFs, then compare the AI-generated text with InFoDat information displayed through Power BI.

⚠
AI output requires human validation.Do not treat an extracted value as authoritative until qualified personnel compare it with the source document, supporting references, and applicable program data.
Retrieve

Find documents

Open the built-in Document Download screen and use the embedded Power BI report to locate FMP/FIA documents.

Analyze

Extract metrics

Submit an FMP PDF, FIA PDF, or both. The workflow uses text recognition and custom prompts to identify relevant passages.

Validate

Compare results

Review Plan Period, Commercial Volume, AAC, IAC, and RAC output beside the InFoDat Power BI report.

The solution reduces repeated searching, manual reading, copy-and-paste consolidation, and switching among separate tools. It does not approve data, update InFoDat, or make forestry program decisions.

2. Before you begin

  • Use an authorized organizational account and approved device/network.
  • Confirm access to the Power App and both embedded Power BI reports.
  • Use only documents permitted for the deployment environment.
  • Do not upload PII. The application notice states that it is not designed or approved to process PII.
  • Prepare PDF files no larger than 20 MB, as stated in the app.
  • Know the tribe name and relevant FMP/FIA year before submitting.
i
Power BI permissions are separate.Being able to open the canvas app does not necessarily grant access to an embedded report. Request report access through the approved support channel.

4. Get FMP and FIA documents

Open Document Download.On the home screen, select Click to Access beneath “Download FIA & FMP Documents for AI Analysis.”
Wait for the embedded report.Sign in or request Power BI access when prompted. Allow report visuals and filters to finish loading.
Filter to the correct record.Use the report's tribe, document type, year, or other available filters. Confirm that the selected document belongs to the intended tribe and reporting context.
Download through the approved control.Store the document only in an approved location and preserve its original filename when practical.
Return home.Select Home at the bottom of the Document Download screen.
!
Check before upload.A similar title or year does not guarantee that a document is correct. Confirm tribe, document type, period, and approval status.

5. Prepare files

RequirementGuidance
FormatUse PDF. The workflow identifies DOCX as an invalid document type and directs users to convert it to PDF.
SizeKeep each PDF at or below 20 MB, as stated in the app. For a larger PDF, use an approved PDF-reduction process before uploading.
CountOne FMP attachment and one FIA attachment maximum per submission.
QualityUse the clearest approved copy available. Poor scans, missing pages, rotated text, handwriting, and complex tables may reduce extraction quality.
ContentDo not include PII. Confirm the document is allowed within the app's authorization boundary.
Which combination can I submit?

You may submit FMP only, FIA only, or both. At least one valid document should be attached. Enter the corresponding year for each selected document.

How should I reduce a large PDF?

Use an approved PDF application and your organization's authorized “reduced size” or optimization function. Reopen the reduced file, confirm all pages are present and readable, and verify that the file is 20 MB or smaller.

6. Run the analysis

Close the welcome popup.Read the instructions and select Let's Go!.
Enter the tribe name and requested email.Check spelling and avoid extra spaces. Use the approved contact address for the deployment.
Enter the applicable year(s).Complete the FMP year, FIA year, or both to match the attached documents.
Attach the PDF(s).Select Click to Attach in the FMP and/or FIA area. Confirm the displayed filename is correct.
Confirm each document toggle.The FMP or FIA toggle should be on for every attached file that should be analyzed.
Submit once.Select Submit for Data Metrics. A submission message appears and the app moves to Results while processing continues.
⚠
Avoid duplicate jobs.Do not select Submit repeatedly or start another submission merely because results are not immediate. Record the time and follow the troubleshooting procedure first.

What happens after submission

The flow creates a queued SharePoint job, returns a job identifier to the app, changes the job to running, recognizes text, processes the selected metric prompts, and writes the completed output. Processing time depends on document length, scan quality, service capacity, and system availability.

When the Results screen opens, read the instruction popup and select Close. The left side displays AI-generated text; the right side displays the embedded InFoDat report.

8. Use the embedded Power BI reports

Document Download report

Use this report to locate FMP/FIA documents before analysis. Apply filters carefully, verify the correct record, and use only approved download or link controls.

InFoDat comparison report

Use the report on Results to compare AI-generated output with current authorized reporting. The report is read-only from the app user's perspective; interacting with filters does not change InFoDat data.

Filter

Select the intended tribe, period, document type, or other available context. Hidden filters can change what a visual shows.

Inspect

Use tooltips, focus mode, drill, or detail views only when enabled and appropriate.

Reset

Clear selections or reset to the report's default state before concluding that data is missing.

i
Access and refresh matter.A blank report can result from missing Power BI permission, filters, network/service issues, or refresh timing. Browser refresh does not necessarily refresh the underlying semantic model.

9. Security, data handling, and responsible AI use

⚠
No PII.The application notice states that no PII is used and that the solution is not designed or approved to process PII. Do not upload PII without explicit prior authorization and a formally approved change to the system.
  • Use the app only for authorized work and approved document types.
  • Handle CUI and tribal data within the approved environment and sharing boundaries.
  • Do not paste document text or AI output into public issues, chat systems, or unapproved tools.
  • Do not treat AI output as a final decision, approval, or authoritative record.
  • Watch for prompt injection or instructions embedded in documents; report unusual output.
  • Store downloads and exports only in approved locations and follow records requirements.
  • Use the minimum necessary information in support tickets.

AI use in the solution

The production workflow uses AI Builder for text recognition and custom-prompt analysis. DOI-approved Copilot Chat also supported development and iterative updates such as drafting, formula refinement, testing ideas, troubleshooting, and documentation. In both cases, people remain responsible for validation, testing, approval, and deployment.
